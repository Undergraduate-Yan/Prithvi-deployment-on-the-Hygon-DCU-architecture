# Phase 11：K100 混合精度与部署收口报告

> 日期：2026-08-18  
> 状态：最终冻结快照 v2（FP32、FP16 full、M0–M5、kernel、同 CLI 性能与双节点部署验收均已完成）  
> 硬件边界：海光 K100 即目标边缘硬件，不扩展 Jetson/Myriad，不引入 D=256 Dual-MAE 学生模型。

## 1. 当前结论

1. **同协议 FP32 基线补救成功。** 在 FP32 25 段 head 的 `fpn4 MaxPool` 输出处增加 graph-output barrier 后，CPU logits 与修改前逐元素一致；固定 90 样本结果与冻结 FP32 完全一致，25 段均满足 MIGraphX 事件大于 0、CPU provider 事件为 0，段间输出保持设备 OrtValue。该结果已经可以作为同协议速度分母。
2. **M0–M5 均通过任务级准入和三轮复验。** 六个候选均完成 90/90 样本、固定有效像素 `3,927,398`、非有限输出为 0；mIoU、Water IoU、corrected Boundary Water IoU 三轮跨度均为 `0.000000 pp`。
3. **M0 原始正式性能仍为 `unstable`。** 原始 M0 model-only trial-median CV 为 `6.474904%`，超过 `5%` 门槛。后续 M0 单候选确认的 CV 已降至 `0.568234%`，但它只能作为追加观察，**不得覆盖原始 M0，也不恢复其 combined Pareto 资格**。
4. **角色分工已经清楚：** M1 是平衡型和合格候选中 ONNX+MXR 最小者；M4 是任务精度字典序最优者；M5 是端到端 median 最低者。M1–M5 均位于当前多目标 Pareto 前沿。
5. **M5 与同协议 FP32 只能称为近似持平。** M5 端到端 median 为 `22.0803325 ms`，FP32 为 `22.2092840 ms`，形式比值为 `1.005840×`，即 median 仅低约 `0.5806%`；model-only 只低约 `0.0472%`。同时 M5 的 P95/P99 均未优于 FP32。因此不能把 M5 表述为有实质意义的“INT8 加速”。
6. **严格 logits 等价永久保留为 failed。** M0 的历史 strict failure 未被任何任务级结果覆盖；M1–M5 当前也没有通过 strict logits 门槛。任务等价、provider placement 和绝对时延均不能改写这一结论。
7. **逐 block kernel 路径已经证明。** 33 个去重 trace 和 144 个候选/block 映射全部通过；保留 INT8 的 block 均观察到 `I8II`，FP16 block 均观察到 `HBH`，且全部目标 session 为 MIGraphX>0、CPU=0。该证据只证明 block 级 GEMM 路径，不证明整模型全部算子为 INT8，也不单独证明模型级加速。
8. **M5 与 FP16 full 均通过正式部署验收。** 两个 bundle 均通过静态校验、5/5 冷启动、3/3 主动终止后恢复、K100-2/K100-3 smoke 和 60 分钟稳定性；最终聚合器状态为 `passed`。
9. **M5 通过完整部署容量门槛，但未通过时延升级门槛。** M5 完整 payload 比 FP16 full 小 `23.463061%`，但同一部署 CLI 下 median 时延为 FP16 的 `1.736423×`，慢 `73.6423%`，明显超过“不慢于 5%”的升级条件。
10. **最终推荐仍为 FP16 full。** M5 是可运行、容量优先的混合精度候选，适合作为论文消融结果；由于同 CLI 时延门槛失败，不替换 FP16 full。严格 logits failure 仍永久保留。

## 2. 冻结实验协议

### 2.1 任务级准入

- 输入：`1×6×224×224`，batch=`1`。
- 数据：固定 90 样本，固定有效像素 `3,927,398`。
- 门槛：mIoU 下降不超过 `0.5 pp`；Water IoU 下降不超过 `1.0 pp`；corrected Boundary Water IoU 下降不超过 `1.0 pp`；预测一致率不低于 `99.5%`；非有限输出为 0。
- 稳定性：3 个独立新进程；mIoU/Water IoU 三轮跨度不超过 `0.01 pp`，Boundary IoU 跨度不超过 `0.02 pp`。
- strict logits：只作为永久保留的诊断列，不是任务性能轨的硬前置。

### 2.2 正式性能

- 25 个常驻 MIGraphX 会话，段间使用设备 OrtValue。
- batch=`1`；每个 scope 预热 30 次；每个新进程测量 100 次；共 3 个独立新进程。
- 主表使用“三轮 trial median 的中位数”；P95/P99 同样使用三轮对应统计量的中位数。合并 300 次调用的统计只可作为描述性结果。
- 两个 scope：`model-only` 与统一的 `end-to-end input→logits`。
- trial-median CV 不超过 `5%` 才允许正式速度表述。
- 速度比定义为 `同协议 FP32 median / 候选 median`；小于 `1.0×` 表示候选更慢。

## 9. Combined Pareto 与当前角色

冻结合并结果状态为 `completed_with_frozen_m0_original_unstable_excluded`：

- Pareto 合格候选：`M1, M2, M3, M4, M5`。
- 当前多目标前沿：`M1, M2, M3, M4, M5`。
- M0 排除原因：原始 model-only trial-median CV 超过 `5%`；追加确认不得覆盖冻结原始运行。
- 任务精度字典序最优：**M4**。
- ONNX+MXR 最小：**M1**。
- 端到端 median 最低：**M5**。
- 增量显存最低：**M2**。
- 平衡 Pareto：**M1**，normalized mean regret=`0.1881494701`。

因此，论文可以把 M1、M4、M5 分别作为“容量/平衡”“精度”“时延近似持平”三种代表点，但不能把其中任何一个提前写成正式部署模型。

| M0 | 24 | 0 | 24/24 通过 | 不适用 | 全通过 | block 级 INT8 GEMM 路径通过 |
| M1 | 23 | 1 | 23/23 通过 | 1/1 通过 | 全通过 | 通过 |
| M2 | 22 | 2 | 22/22 通过 | 2/2 通过 | 全通过 | 通过 |
| M3 | 21 | 3 | 21/21 通过 | 3/3 通过 | 全通过 | 通过 |
| M4 | 20 | 4 | 20/20 通过 | 4/4 通过 | 全通过 | 通过 |
| M5 | 15 | 9 | 15/15 通过 | 9/9 通过 | 全通过 | 通过 |

该结果允许写“保留 INT8 block 的实际 GEMM kernel 路径识别到 `I8II`，FP16 block 识别到 `HBH`”。边界必须同时保留：这不是“整模型所有算子均为 INT8”的证明，也不单独证明模型级加速；direct trace 含 session/MXR 加载与 H2D/D2H，Q/DQ、Cast、layout 与 Memcpy 的占比不是纯稳态占比，HIP/HSA Memcpy 时间也不能与 GPU kernel 时间直接相加。此前动态 `hipprof --session --start` 失败属于方法失败，未计入 kernel 结论。

## 12. 论文结论与部署决策

### 12.1 可以正式报告的事实

- FP32 25 段同协议基线已完成任务准入和正式性能，可作为匹配 scope 的速度分母。
- M0–M5 均通过固定 90 样本任务级门槛，三轮任务指标完全稳定；M1–M5 通过正式性能 CV 门槛，M0 原始运行仍为 unstable。
- M1 是容量/平衡代表，M4 是任务精度代表，M5 是同协议 FP32 下端到端 median 近似持平代表。
- 33 个 kernel trace 与 144 个映射证明保留 INT8 block 出现 `I8II`、FP16 block 出现 `HBH`；这是 block 级实际 GEMM 路径证据。
- M5 完整部署 payload 比 FP16 full 小 `23.463061%`，容量门槛通过。
- M5 与 FP16 full 均通过双节点操作性部署验收和 60 分钟稳定性。

### 12.2 最终推荐

| 模型 | 操作性部署验收 | 容量门槛 | 同 CLI 时延门槛 | 推荐状态 |
|---|---|---|---|---|
| FP16 full | passed | 基线 | passed/基线 | **正式部署首选** |
| M5 | passed | passed（小 `23.463061%`） | **failed**（慢 `73.6423%`） | 容量优先的论文消融/可部署候选，不替换 FP16 |

M5 虽然可部署且容量更小，但未满足“同一端到端 CLI 时延不比 FP16 慢超过 5%”的预设升级条件。因此最终推荐模型仍是 **FP16 full**；M5 保留为任务级混合精度、kernel 路径和容量权衡的论文结果。

### 12.3 永久禁止的误述

- 禁止写“strict logits 等价通过”或用任务指标覆盖其 failure；
- 禁止用 M0 追加确认覆盖原始 unstable；
- 禁止把 M1–M4 相对 FP32 更慢的结果写成加速；
- 禁止把 M5 对 FP32 约 `0.6%` 的差异归因于 INT8 kernel；
- 禁止把 block 级 `I8II` 扩写为“整模型所有算子均为原生 INT8”；
- 禁止写“M5 已替换 FP16 full”或把操作性部署通过等同于推荐升级通过。
